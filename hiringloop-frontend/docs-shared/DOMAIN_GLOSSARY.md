# HiringLoop Domain Glossary

These are project-specific meanings inside HiringLoop.

| Term | Meaning in HiringLoop |
|---|---|
| Organization | The tenant/workspace that owns recruiting data and defines the authorization boundary. |
| User | A global person/account identity that may authenticate and participate in one or more organizations. |
| Membership | A User's organization-specific relationship, status, and effective role/permission context. |
| Candidate | An organization's reusable recruiting profile for a person across potentially multiple applications. |
| Application | One Candidate's candidacy for one Job, including job-specific answers, stage, status, and history. |
| Job | A hiring requirement/requisition and its job-specific configuration. |
| Pipeline | The workflow configuration through which applications for a job move. |
| Pipeline Stage | One ordered step in a Pipeline used as an application's current placement and historical transition context. |
| Interview | A scheduled or conducted recruiting event associated with an Application and participants. |
| Interviewer | An authorized User or explicitly supported participant assigned to evaluate an Interview. |
| Scorecard | An evaluation instance assigned to an Interviewer for an Interview, based on a template. |
| Feedback | Ratings, answers, and comments submitted through a Scorecard or approved evaluation workflow. |
| Activity | User-visible business history explaining recruiting work and lifecycle changes. |
| Audit | Protected security/administrative history of who changed what, when, and in which context. |
| Offer | A proposal of employment terms made to a Candidate within an Application/Job context. |
| Hire | A business outcome or explicit transition after recruiting; not automatically the same as Offer acceptance. |
| Reject | An application outcome/exit that stops active progression while preserving permitted history. |
| Talent Pool | An organization-managed collection of Candidates for future recruiting use, independent of application stage. |
| Communication | An outbound/inbound message intent and delivery history, such as an email to a candidate. |
| Notification | An in-product/user-facing alert for a User, often reacting to another domain's activity. |
| Resume | An uploaded source document containing a candidate's employment/application information. |
| Document | A candidate- or offer-related uploaded resource with metadata, ownership, access, and version/history. |

Exact states, retention, visibility, and product behavior not confirmed by current project material are marked **Proposed / Requires Product Decision** in the domain model.
