### Suggested minimum release evidence

- UI-to-real-HTTP contract checks for E03-E05 and role denials.
- PostgreSQL integration for scorecard rollback/partial-save policy, interview participant/history integrity, notification projection and concurrent overlap handling.
- Mail acceptance/network ambiguity/status-write failure and crash/replay experiments with a deterministic provider harness.
- Resume conditional-write replay and signature mismatch checks; production S3 CORS/policy verification, full document scanning and storage-side upload-size cap remain.
- All forward SQL migrations applied from empty in staging; custom constraints/indexes/triggers verified.
- Full backend test selection, frontend tests/typecheck/build, lint/format gates and clean diff.
- Hosting TLS/cookie/CORS/proxy behavior, readiness, logs/metrics and backup restore with agreed recovery objectives.

These activities were not executed. Complexity estimates are surface estimates, not time commitments. Keep the modular monolith while these risks are resolved; no source evidence establishes a need to split services.

## INFERRED

Stages 1-3 address immediate correctness; stages 4-7 are release-risk work. Some items can proceed independently with explicit ownership, but immutable storage design precedes scan/retrieval guarantees, and provider classification precedes safe automatic retries. Redis/BullMQ in the roadmap is a possible implementation tool, not a substitute for idempotent claims and recovery state.
