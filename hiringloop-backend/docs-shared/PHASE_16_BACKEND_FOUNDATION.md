# Phase 16 backend foundation

Communication is one authoritative outbound candidate EMAIL attempt. Its recipient is a Candidate-email snapshot obtained through the tenant-scoped Application; no `CommunicationRecipient` exists because arbitrary, multi-recipient delivery is outside the model. State checks enforce PENDING (no terminal timestamp), SENT (sentAt only), and FAILED (failedAt only); content checks reject blank values. The idempotency key is unique by organization, application, sender, and client UUID. Provider success becomes SENT, explicit errors become FAILED, and ambiguous outcomes remain PENDING without an automatic resend.

Templates are tenant-local, unique by organization/name, and revision guarded. Notifications target exactly one Application or Interview. Preferences are backed by OrganizationMembership, with a missing row meaning enabled. Candidate communication failures are mandatory sender notifications. Interview schedule/reschedule/cancel notifications go only to current participants other than the actor; scorecard submission goes only to the interview creator when different from the submitter. Informational notifications respect preferences.

The send endpoint is limited to 30 requests/hour per authenticated user, resolved tenant, and client IP using the existing in-memory limiter. Communication history, templates, and inbox use page/pageSize (default 25, maximum 100) with deterministic ordering. SendGrid is synchronous in this phase; BullMQ/retry/reconciliation are Phase 19 work, and provider webhook/realtime reliability are Phase 20 work.
